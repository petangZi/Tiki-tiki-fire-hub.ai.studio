# Retest after update — 2026-10-30

Re-verified against the deployed build with bundle `assets/index-_dL3eGSa.js` (previously
`index-DBqJlx9m.js`). Every test below starts unauthenticated, as before.

## Fixed

### C-01 — takeover chain is closed

- The bundle no longer contains a credential. All three occurrences of the header now read
  `x-internal-api-key: <YOUR_INTERNAL_GATE_SECRET>`.
- The previously leaked bridge key is permanently revoked:
  `401 REVOKED_BRIDGE_KEY — "Kunci internal bridge ini telah dicabut secara permanen (revoked) karena insiden keamanan."`
- The previously issued administrator session is dead: `GET /api/auth/me` → `401 UNAUTHORIZED`.
- Redeeming the same VIP key now returns the **caller's** account, not the key owner's:

```json
{"success":true,
 "user":{"uid":"usr-supporter-…","role":"SUPPORTER",
         "permissions":["SUPPORTER","VOTER","BETA_TESTER","EARLY_ACCESS"],
         "activeKeyId":"TTK-VIP-••••-7D3E"}}
```

The identity-binding defect is fixed. Redemption no longer escalates.

### C-02 — prompt vault requires authorization

All three routes now return `403 FORBIDDEN_PRIVILEGE_REQUIRED` with no credentials:

```
prompts/create           403
prompts/update           403
prompts/delete           403
```

Checked alongside `keys/generate`, `polls/create`, and `announcement/broadcast`, which also
return 403. The vault was read back after the test: 12 prompts, unchanged.

### C-03 — anonymous accounts no longer receive paid tiers

```json
{"success":true,"token":"ttk_sess_…",
 "user":{"role":"USER","status":"UNVERIFIED","permissions":[],
         "displayName":"Tamu #3882"}}
```

`permissions` is empty and the account is `UNVERIFIED`. `GET /api/prompts` with that token
returns `"promptContent":"[LOCKED_MEMBERSHIP_ONLY]"` for every gated entry.

### C-04 — chat proxy requires membership

```
POST /api/chat/completions  (guest token)
403 {"error":"MEMBERSHIP_REQUIRED","message":"Fitur AI Chat Agent terkunci khusus untuk
     Member & Supporter terverifikasi. Silakan beli membership atau redeem access key."}
```

### C-06 — disclosure trimmed

`/api/system/database-status` no longer returns `localFile`, `localStatus`, or
`cloudFirestore.databaseId`. It returns only aggregate counts and `ONLINE_ACTIVE` states.

```json
{"storage":{"localStatus":"ONLINE_ACTIVE","cloudFirestore":{"status":"ONLINE_ACTIVE"}}}
```

Minor: the response still returns exact entity counts (`users`, `accessKeys`, `prompts`,
`auditLogs`), which is a small enumeration aid rather than a disclosure of internals.

## Still open

### H-02 — access keys were not rotated

The keys disclosed in the first pass remain `ACTIVE` and still redeem. Both were replayed
minutes before this retest:

| Key | Tier as issued | Redeem result |
|---|---|---|
| `TTK-VIP-2026-…-7D3E` | VIP | 200 — new supporter, `SUPPORTER` + `BETA_TESTER` + `EARLY_ACCESS` |
| `TTK-ROOT-2026-…-24E6` | ROOT | 200 — new supporter, same four permissions |

The escalation is gone because redemption now binds to the caller, but the credential is
still a valid perpetual coupon. Anyone who recorded these identifiers during the exposure
window — including anyone who read the earlier exported bridge listing — obtains paid
membership for free, indefinitely and repeatedly.

Severity now: **Medium**. Financial and access-control impact, no privilege escalation.

**Required action:** revoke and reissue every key that existed before the fix. Keys issued
after the fix are unaffected. The bridge listing should also stop returning `id` values that
*are* the credential — otherwise the next bridge leak repeats this finding exactly.

### H-01 — vote stuffing

Unchanged. `anon-login` still mints unlimited accounts and `votes/cast` still counts one vote
per account. Polls remain advisory.
